## 一、4.1 故障库扩展（本轮已做）

扩展前合成器只支持 `none / bpfo / bpfi`，且三者共用同一条冲击串公式——"测试数据、规则基线与
智能体诊断共享同一套物理假设"，能在自造的理想信号上正确识别，不足以说明能处理未知工况。

现在 `phmlite/dsp.py` 支持 7 种机理，且**可分性由测量证实**（`tests/test_fault_physics.py` 11 项）：

| 机理 | 物理含义 | BPFO | BPFI | BSF | FTF | RMS | 峭度 |
|---|---|---|---|---|---|---|---|
| `none` | 正常 | 2.0 | 1.8 | 4.8 | 2.5 | 2.11 | 1.90 |
| `bpfo` | 外圈冲击串 | **195.7** | 5.5 | 1.3 | 4.4 | 6.70 | 10.50 |
| `bpfi` | 内圈冲击串 | 1.8 | **291.9** | 2.5 | 10.4 | 9.17 | 5.98 |
| `bpfo_bpfi` | 混合（外圈+内圈） | **56.8** | **51.6** | 1.1 | 3.8 | 6.05 | 5.77 |
| `unbalance` | 不平衡（1X 占优、无冲击） | 2.8 | 2.2 | 5.3 | 1.6 | 8.17 | 1.53 |
| `looseness` | 基础松动（2X/3X 谐波） | 3.1 | 2.3 | 5.8 | 6.1 | 4.40 | 2.80 |
| `unknown` | 未建模（仅宽频能量） | 1.5 | 2.8 | 2.4 | 1.7 | 8.32 | 3.02 |

数值为**包络谱在特征频率 ±3Hz 的峰 / 10~1000Hz 中位底噪**（fs=16000, N=16384, 2980rpm,
severity=0.8, noise=0.05, seed=42）。结论：轴承类在自身频率上 50~290 倍，非轴承类在**所有**
轴承频率上 ≤6.1 倍——**可区分**，因此"混合/非轴承/未知"三组用例有物理基础，不是凑数。

**判据必须用峰/底噪比**：宽带能量（强噪声、`unknown`）会把包络谱底噪整体抬高，只看绝对幅值
会把"底噪变高"误判成"出现特征峰"。这一条是实测踩出来的（见下表 looseless 一行）。

**实测抓到的一个真问题**：早期 `looseness` 模型混入 0.5X 半频项（那属油膜涡动/whip 机理），
在 BSF 处造出 23.4 倍伪峰（基线 4.8 倍），足以被误判成滚动体缺陷。已移除该项，BSF 回落到 5.8 倍，
并留了回归防止再犯。

| 实验类别 | 本轮之前 | 本轮之后 | 状态 |
|---|---|---|---|
| BPFO/BPFI 单故障 | 4 用例 | 严重程度梯度 0.45/0.6/0.8/0.88 + 边界两形态 | 已补 |
| 不同随机种子 | 未显式覆盖 | 采样循环每次都换种子（seed 随样本序号递推），另有 `test_different_seeds_keep_the_signature` 断言机理不变 | 部分（见"未做"） |

| 变转速 | 1 档（2400） | 1200/2400/2980/3600 四档，含智能体用例与物理断言 | 已补 |
| 工具故障 | 仅 spectrum 503 | spectrum 503 + **trend/charfreq 503（部分数据缺失）** | 已补（超时/限流未做） |
| 混合故障 | **未覆盖** | `bpfo_bpfi` 用例 + 评分器支持混合标签 + 基线可判混合 | 已补 |
| 未知故障 | **未覆盖** | `unknown` 机理（宽频无特征峰）+ 评分器支持 `undetermined`（主动拒绝） | 已补 |
| 真实数据（CWRU/Paderborn） | 未覆盖 | **仍未覆盖**——方案见第四节，本轮未实施 | **未做** |
| 无智能体基线 | 规则方法（幅值阈值） | 规则基线升级为峰/底噪比，**能判混合**（更强的对照才诚实）；耗时/异常恢复/证据质量见下 | 部分 |

**规则基线在新矩阵上的实测表现**（合成器直接驱动，2026-10-13）：

```
[OK ] bpfo-standard   bpfo        -> bpfo        BPFO=195.7 BPFI=5.5
[OK ] bpfi-standard   bpfi        -> bpfi        BPFO=1.8   BPFI=291.9
[OK ] mixed-bpfo-bpfi bpfo_bpfi   -> bpfo_bpfi   BPFO=59.5  BPFI=54.7     ← 基线现在能表达混合
[OK ] unbalance-1x    normal      -> normal      BPFO=2.9   BPFI=2.2      ← 不把非轴承机理误判成轴承缺陷
[OK ] looseness       normal      -> normal      BPFO=3.0   BPFI=2.3
[差异] bpfo-lowrpm    bpfo        -> bpfo_bpfi   BPFO=97.4  BPFI=80.7
[差异] unknown        undetermined-> normal      BPFO=1.5   BPFI=2.8
```

两处差异都是**真实局限**，不修掉、如实记录：

1. **1200rpm 低转速下单故障不可分**：fr=20Hz 时 BPFO=54.4Hz 与 BPFI=81.6Hz 只差 27Hz，
   冲击串的谱泄漏会同时落进两个 ±3Hz 带内（BPFO 97.4 / BPFI 80.7 都超阈）。
   这是低转速轴承诊断的公认难点，也说明 **±3Hz 判据在低转速下需要更窄的容差或更高的谱分辨率**。
   该用例保留：它是合法的难例，智能体若能用包络谱细节或时域冲击间隔区分，正是差异化能力。
2. **基线无法表达"能量异常但机理不可识别"**：`unknown` 用例真值 `undetermined`，基线只能给
   `normal`。这是规则方法的结构性限制（它的输出空间只有轴承频率与正常），也正是
   `undetermined` 这一档存在的意义——**智能体应当能说"异常但无法定性"，规则基线不能**。

**评分器修正（本轮）**：旧 `classify_text` 只认 BPFO/BPFI/正常，混合故障会被记成
`abnormal-untyped`。现在支持 `bpfo_bpfi` 与 `undetermined`，并且**不被否定表述骗到**——
真实结论会写"BPFI/BSF/FTF 区无主导峰"来排除某频率，数关键词会把外圈故障误判成混合。
处理方式：同一分句内前后窗口查否定词，并用分句符截断（`排除 BPFO，内圈 BPFI 命中` 里的
"排除"不能算到 BPFI 头上）。回归用**真实结论文本**（库中 28 条 reports.conclusion）锚定。

**证据质量维度（本轮新增）**：`is_hedged()` 区分"确证结论"与"倾向性/待复测确认"。
真实数据里报告 #21、#27 属于后者（工具故障下的保留性结论），只看 `said == truth` 会把它们
和确证结论记成同一档。

## 三、数据口径（4.1 后半）

| 来源 | 标记 | 说明 |
|---|---|---|
| 程序合成信号 | 无独立标记 | 由 `data/scenario.json` 场景驱动；**不是现场测量值** |
| 24h 历史种子 | `eigen_history.origin = 'seed'` | `seed.py` 的确定性随机（seed=7），**是模拟历史曲线，不是设备真实连续运行记录** |
| 实时采样 | `eigen_history.origin = 'live'` | 由独立采样循环写入（P0 问题3），报警绑定样本序号 |
| 建库早于来源标记的行 | `origin = 'unknown'` | 迁移时**不猜**：宁可标"未判定"，也不把模拟历史冒充成真实采样 |

`GET /api/trend` 现返回 `seeded_points` / `live_points` / `unclassified_points` 与每个点的
`origin`，前端与评委可据此区分，不再把种子数据当成现场故障演化。

## 四、引入 CWRU / Paderborn 的方案（**未实施**）

评审给的两个数据集都是**轴承实验台**数据，不是调相机现场数据。按评审自己的提醒，
不能把它们代入 P-101 参数后声称"调相机现场诊断准确率"。拟定的适配协议：

1. **独立通道**：新增 `datasets/` 适配器，把外部数据映射为 phmlite 的"波形输入"，**不**改
   `CHANNEL_SPECS` 与 P-101 阈值；结果标注为"轴承实验台数据（CWRU/Paderborn）"。
2. **参数换算**：采样率、轴承节径比、滚珠数、接触角、单位（g vs m/s² vs μm）逐项显式声明并
   随结果一起记录；CWRU 的 12kHz/48kHz 与 1797/1750/1730rpm 需分别对待。
3. **判据不变**：仍用包络谱 ±3Hz 峰/底噪比，但容差与底噪频段按新采样率重算。
4. **报告口径**：只报告"在这些实验台数据上的分类表现"，与合成集结果**并列**而不混算；
   不得合并成一个"总体准确率"。
5. **预期价值**：检验泛化（不同轴承参数/转速/损伤程度/噪声），以及"域外数据上是否会
   过度自信"——这正是 `unknown`/`undetermined` 用例要防的问题。

**未实施原因**：需要下载与解析外部数据集（数十 MB 二进制 .mat），且适配器本身是一个独立
子项目；在演示链路尚未做真机端到端验收前做它，优先级低于把现有链路验通。

## 五、未做清单（不回避）

- 外部真实数据集（CWRU / Paderborn）**完全未做**；本文件不声称任何现场诊断准确率。
- 工具**超时**与**模型限流**用例未做（只做了 503 类工具失败与部分数据缺失）。
- "不同随机种子"只做了物理层断言；端到端层面靠采样循环自动换种子，**未做**固定种子的
  对照实验矩阵。
- 无智能体基线的**耗时/异常恢复/证据质量**对比：基线耗时未测；异常恢复（工具故障下是否降级
  完成）在 `bpfo-tool-failure` 用例里记录，但未与规则基线逐项对照。
- **端到端一次都没重跑**：本轮所有改动（故障库、评分器、覆盖矩阵）只跑了离线单测与物理断言；
  智能体在新增机理（混合/非机械/未知）上的实际表现**尚未实测**。
