# AGH 统一调用与人工备用模式设计

状态：已通过用户审阅
日期：2026-10-05

## 目标

让 Agnes/AGH 成为所有模型驱动功能的唯一执行路径。AGH 或 Agnes 凭据不可用时，系统明确报告智能体功能不可用，不用本地规则伪装诊断闭环；操作员可主动切换到人工备用模式，使用基础监测、报警和人工处置。

系统采用合成仿真数据，因此“人工备用模式”指不依赖智能体的基础平台模式，不表示真实调相机的控制或保护系统。

## 赛事约束与定位

赛事官方技术规则要求作品以 Agnes Harness（AGH）作为智能体运行与执行底座，经 AGH 完成至少三个连续步骤，并仅调用 Agnes 模型。规则没有要求移除智能体后底层监测与报警必须停止。

本作品的参赛主线是：仿真测点监测与阈值报警作为工业系统底座；AGH 智能体增加自主取证、交叉验证、结论置信度、报告与工单等能力。演示需清楚区分这些层次，证明诊断闭环确由 AGH 执行。

## 运行模式

### 智能体增强模式

- 基础监测、趋势、阈值分档与报警持续运行。
- AGH 可用且 Agnes Key 已配置时，严重报警可唤起 AGH 执行自主取证、诊断、报告与工单流程。
- 吉祥物聊天、聊天操作及操作结果总结全部经 AGH；PHMLite 不直接请求 Agnes API。
- 服务端继续对白名单操作做校验；聊天模型输出不能越权执行。

### 人工备用模式

- 操作员可在 AGH 不可用时主动进入；页面明确显示“人工备用模式”。AGH 恢复后不自动切回，由操作员决定。
- 当前运行模式保存在本地配置中；重启后保留人工备用模式。新部署若尚未配置 Key 或 AGH 不可用，显示“智能体不可用”，不得假报为增强模式已就绪。
- 保留基础监测、报警、趋势和设备视图，以及人工查看、确认和处置报警的能力。
- 禁用自动诊断、智能体聊天与由模型发起的操作；人工创建的任务须标记为人工来源。
- 不生成自动诊断结论、证据链、置信度或智能体来源工单。

### AGH 离线或模型调用失败

- 不自动调用本地规则诊断，不写入报告或自动工单。
- 报告与智能体工单写入接口只接受当前运行中的 AGH 诊断 `run_id`；工单记录保存该 `run_id`。AGH 会话失败时回滚本次 run 已写入的智能体报告和工单。
- 自动诊断状态以失败收尾，原因明确区分运行时离线、凭据未配置、模型调用失败或超时。
- 正在进行的 AGH 会话失败时，不把报警时间推算成“取证中”或“交叉验证”；专家诊断页、工作流页和吉祥物显示明确失败状态。
- 基础监测和报警不因 AGH 离线而停止。未进入人工备用模式前，页面显示智能体功能不可用，并提供人工备用入口。

## API Key 配置

- 新增系统设置页，提供 Agnes API Key 密码输入框、保存状态及经 AGH 执行的连接验证。
- Key 由本地 PHMLite 后端原子写入当前 AGH profile 的 Agnes 凭据引用目标，作为 AGH 与模型调用的唯一密钥来源；不写入浏览器存储，不由 API 回读，不写入应用日志。设置状态接口只返回是否已配置，不返回 Key 或其片段。
- 写 Key 的接口仅接受本机回环请求和同源请求；Key 不放入 URL、命令行参数或错误信息。
- 使用 AGH 凭据库既有结构及本机私有 ACL。凭据路径由当前 profile 的 `credentialRef` 解析；不得假定所有部署都使用当前机器的固定文件路径。
- Key 验证失败时保留可修正配置状态并显示错误，不假报可用。若当前 AGH 构建缓存凭据，界面明确提示需要重启运行时后再验证。
- 部署所需的 AGH 路径仍通过运行时配置提供；设置页负责录入和配置 Agnes Key，不负责下载或安装 AGH。

## 影响范围

- `phmlite/agnes_chat.py`、`phmlite/server.py`：聊天全部改走 AGH；保留白名单动作执行。
- `phmlite/autodiag.py`：移除离线本地规则诊断回退，清楚报告 AGH 失败。
- `dashboard/src/App.jsx` 及新增系统设置页面：加入模式状态和 Key 设置入口。
- `dashboard/src/pages/AgentDiagnosis.jsx`、`dashboard/src/pages/Workflow.jsx`、`dashboard/src/global-agent/GlobalAgent.jsx`：以真实状态驱动展示；不再伪造进度或成功。
- `README.md` 及部署说明：说明 Key 设置、AGH 依赖和仿真数据口径。

## 验收条件

1. 所有大模型请求均通过 AGH，仓库运行路径不再直接请求 Agnes Chat Completions API。
2. AGH 停止、Key 缺失、Key 无效或模型调用失败时，聊天和自动诊断明确失败；不生成规则诊断报告、置信度或自动工单。
3. AGH 离线时基础监测和报警仍可用；人工备用模式须由操作员明确进入，界面清楚标识该模式和被禁用的智能体功能。
4. AGH 恢复后人工备用模式不自行变回智能体模式；操作员能明确切回并确认智能体可用。
5. 本地部署者在设置页录入自己的 Key 后，AGH 可用该 Key 完成连接验证与后续智能体调用；Key 不出现在浏览器存储、响应正文或应用日志。
6. README 说明演示数据是程序合成仿真信号，不再含“未使用真实设备或客户数据”的附加句，也不暗示有现场实测数据。
7. 报告与智能体工单必须绑定当前运行中的 AGH `run_id`；没有活跃匹配会话时写入被拒绝，AGH 会话失败后不保留该 run 的部分智能体产物。

## 不在本次范围

- 改造仿真信号算法或接入新的现场设备数据。
- 提供远程密钥管理、多租户密钥隔离、Agnes API 地址或模型选择界面。
- AGH 离线时停止底层监测或阈值报警。
