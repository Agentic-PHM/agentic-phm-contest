# 智能体开关对照实验设计

状态：已按用户确认方向实现；A/B 实测记录见 `evidence/agent-switch-ab-2026-10-06.md`
日期：2026-10-06

## 目标

让评审能在同一平台上直接比较智能体增强模式与人工备用基线：开启智能体时，严重报警可由 AGH 完成取证、诊断、报告和工单；关闭智能体时，只保留基础监测与阈值报警，不再显示吉祥物、聊天或主动播报。

## 当前实现与缺口

- 顶部已有持久化的 `agent` / `manual` 模式切换，不新增第二个开关。
- 后端人工备用模式已经阻止自动诊断、聊天、智能体报告和智能体工单；基础监测与阈值报警继续运行。
- `GlobalAgent` 仍在全局挂载。即使处于人工备用模式，它仍显示吉祥物并执行零 LLM 的规则巡检播报，容易让“关闭智能体后只剩报警”的对照口径不清楚。
- 现有 `evidence/checklist.md` 说明了基线，但没有本版本、同一故障下的 A/B 结果记录。

## 方案

复用现有模式开关和模式 API。前端确认 `mode=manual` 后卸载全局吉祥物；卸载会一并停止聊天面板、定时巡检、事件播报及其轮询。监测页面、采样、趋势和阈值报警保持运行。顶部继续显示“人工备用模式”，其操作说明明确指出智能体展示与主动播报已关闭。

智能体模式保持现有 AGH 流程。AGH 或模型失败时继续使用既有失败状态，不生成本地规则诊断结论或智能体产物；本设计不改变人工备用模式与智能体模式的持久化和切回验证规则。

不增加一键故障注入向导。A/B 演示使用已有人工故障注入入口和顶部模式切换，避免后台自动修改持久化场景或意外污染报告、工单数据。

## 对照实验步骤

1. 记录实验前的运行模式、场景、报警/报告/工单数量；将场景复位为 `fault.type=none`。
2. 确认 AGH 与 Agnes 可用，选择智能体增强模式，注入固定的 `BPFO / severity=0.8`。
3. 等待自动诊断结束，核对本次 `run_id`、AGH 取证记录、报告 ID 和智能体工单 ID；记录耗时和报警状态。
4. 复位场景，明确切换到人工备用模式；确认吉祥物和主动播报消失。
5. 再次注入相同故障，确认通道变化与阈值报警仍发生，自动诊断不启动、报告与智能体工单数量不增加。
6. 将场景复位为 `none`，恢复实验前模式；保留本次 A/B 结果作为独立验证材料。

实验不得删除原有数据库记录。若实验前不是 `agent` 模式，结束时恢复原模式；若某一步失败，记录失败及状态，不将其写成成功闭环。

## 影响范围

- `dashboard/src/global-agent/GlobalAgent.jsx`：仅在智能体增强模式渲染和运行全局吉祥物、聊天、主动播报。
- `dashboard/src/App.jsx`、`dashboard/src/agentState.js`：明确人工备用状态文案；继续使用现有持久化模式开关。
- `dashboard/tests/agent-state.test.js`：覆盖人工备用模式关闭智能体展示的状态判定。
- `evidence/checklist.md` 与 `evidence/manual_check.md`：记录 A/B 方法、条件、结果和未通过项；区分历史彩排与本次验证。
- 后端模式 API 不变；现有 `tests/test_operation_mode.py` 和 `tests/test_autodiag.py` 的人工模式约束继续作为服务端保护。

## 验收标准

1. 选择人工备用模式后，吉祥物、聊天、主动播报不显示/不运行；切回智能体模式后，只有现有 readiness 条件满足才恢复可用状态。
2. 人工备用时基础监测、趋势和阈值报警持续正常；严重报警不会唤起 AGH 诊断，也不会增加诊断报告或智能体工单。
3. 智能体模式下注入固定故障后，当前 AGH 运行必须真实完成并能通过 `run_id` 核对报告、工单和执行记录；否则 A 组记为失败。
4. 两组使用同一故障类型和强度，并记录实验前后计数；收尾复位场景并恢复此前模式。
5. 新增前端状态测试通过；项目 Python 与 dashboard 测试套件通过；前端构建成功。

## 不在本次范围

- 新建另一个“智能体开关”、一键实验向导或自动改写场景的后台任务。
- 改变人工备用模式的监测、趋势、阈值报警、人工工单能力。
- 改变 AGH 诊断流程、模型权限或人工备用模式的持久化方式。
